+# 06 zcode/codex 缓存重叠双重计入修复
+
+Status: ready-for-agent
+
+## 发现
+
+GLM OpenAI 兼容端点的 `inputTokens`(codex 同:`prompt_tokens`)是**含缓存的
+全量 prompt**(OpenAI 语义 cached ⊂ prompt)。zcode/codex 适配器把 input 与
+cacheRead 当互斥类分别入库 → 缓存读双计。
+
+证据(用户 zcode `raw_usage_json`):`totalTokens = inputTokens + outputTokens`
+分毫不差;每请求 `input ≈ read + 1~3k`(真·新增)。结果:zcode 命中率 49%
+(真实 ≈97%),当日 token 总量虚高一倍。
+
+## 定案
+
+User 拍板:修 zcode+codex。gemini 适配器 `subtractCachedOverlapTokens`
+(parser.go:395)是仓库内现成先例。
+
+## 改动
+
+- zcode loader(DB 与 JSONL 两条路径):`Input = input - min(input, read+write)`(clamp)。
+- codex(snapshot.go codexEntries):`Input = input - min(input, cached)`。
+- 测试:zcode loader_test 与 codex 相关测试的 fixture 改为断言扣减后语义(TDD 先红后绿)。
+- 已知代价:CLI zcode/codex 报表数字与 Rust v20 参考不再字节级一致(参考实现疑似同样双计);
+  web.db 历史行需重灌:`token-usage web --since <起始日>`。
+
+## 验收
+
+- 单测:input 含重叠时,入库 Input=差值、CacheRead 不变;read>input 时 clamp 到 0。
+- 全量测试绿。

+# web Dashboard 缓存指标修正与增强
+
+Status: ready-for-agent
+
+## 背景(排查结论)
+
+`token-usage web` 的 /me Dashboard 排查出四类问题:
+
+1. **「缓存命中率 100%」假象**:`read/(read+write)`,不含 input、全历史口径、`%.1f` 进位
+   —— 三者叠加使 100.0% 频繁出现。调查确认:ccusage v20.0.24 无此指标(本仓库自创);
+   claude-usage-dashboard v1.10.0 用 `read/(input+read+creation)`;vLLM 用
+   `prefix_cache_hits / prefix_cache_queries`。业界惯例均含未缓存输入。
+2. **无按工具/模型的命中率**:数据(hourly_usage 五计数器)齐全,纯展示层缺失。
+3. **数字无中文单位**:FormatTokens 用西式 K/M/B,图表 tooltip/轴是裸数字。
+4. 长串数字、口径不透明等衍生体验问题。
+
+## 定案(grilling 两轮,user 拍板)
+
+- **口径 B**:命中率 = 缓存读 ÷(缓存读+缓存写+未缓存输入),当日口径,
+  标签「当日缓存命中率」,两位小数,无封顶。
+- **三比例分解**:命中率卡下堆叠条(读/写/未缓存,和恒 100%)。
+- **30 天命中率趋势线**加进近 30 天图(百分比轴)。
+- **工具 × 模型明细表**(工具/Token/成本/命中率);现有按工具/按模型柱状图
+  tooltip 加命中率与成本(覆盖"按模型成本视角")。
+- **缓存净节省 + 回本次数**当日卡:净节省 = Σ读×(input价−读价) − Σ写5m×(写5m价−input价)
+  − Σ写1h×(写1h价−input价);回本次数 = 当日读 ÷ 当日写。
+- **工作时段热力图**:weekday × hour,全历史,GitHub 贡献图风格。
+- **万/亿单位全站**:`≥1亿 → 1.23亿`(两位小数)、`≥1万 → 4567.8万`(一位小数)、
+  以下原样;FormatTokens + 排行榜 + 所有图表 tooltip/轴统一。
+- 卡片网格:合并「使用工具」「使用模型」为「工具 × 模型」一卡,腾位给净节省卡。
+
+## 词汇表
+
+`server/CONTEXT.md` 已新增 **Cache Hit Rate(缓存命中率)**、**Cache Savings(缓存净节省)**
+词条(实现须与词条一致)。
+
+## 不做(记录在案)
+

+每请求/每 session 级指标(小时粒度数据边界)。

+// CacheSavingsForHourRow prices one cell's Cache Savings: what the cache
+// reads saved by billing at the read rate instead of the input rate, minus
+// the write premium paid to populate the cache. Unknown models contribute 0
+// (no rate card, no honest estimate).
+func (t *PricingTable) CacheSavingsForHourRow(r *HourRow) float64 {
+	card, ok := t.resolve(r.Model)
+	if !ok {
+		return 0
+	}

+	premium := float64(r.Cache5m)*(card.CacheWrite5m-card.Input) +
+		float64(r.Cache1h)*(card.CacheWrite1h-card.Input)
+	return (saved - premium) / 1e6
+}

 **Cache 口径**:
 榜单汇总是否计入缓存 token 的开关:含缓存(全部四类)或仅新增(input+output)。
 
+**Cache Hit Rate(缓存命中率)**:
+输入侧 token 中由缓存读出的占比:缓存读 ÷(缓存读 + 缓存写 + 未缓存输入)。未缓存输入计入分母,故理论上到不了 100%。区别于 Cache 复用率(缓存读 ÷ 缓存读写总量),后者仅作辅助指标。
+_Avoid_: 复用率, cache efficiency
+
+**Cache Savings(缓存净节省)**:
+假设无缓存时本应按输入价计费的费用与实际缓存计费的差额(读便宜、写溢价,均为净值);附带指标「回本次数」= 缓存读 ÷ 缓存写。
+_Avoid_: discount, 省钱金额
+
