# web Dashboard 缓存指标修正与增强

Status: ready-for-agent

## 背景(排查结论)

`token-usage web` 的 /me Dashboard 排查出四类问题:

1. **「缓存命中率 100%」假象**:`read/(read+write)`,不含 input、全历史口径、`%.1f` 进位
   —— 三者叠加使 100.0% 频繁出现。调查确认:ccusage v20.0.24 无此指标(本仓库自创);
   claude-usage-dashboard v1.10.0 用 `read/(input+read+creation)`;vLLM 用
   `prefix_cache_hits / prefix_cache_queries`。业界惯例均含未缓存输入。
2. **无按工具/模型的命中率**:数据(hourly_usage 五计数器)齐全,纯展示层缺失。
3. **数字无中文单位**:FormatTokens 用西式 K/M/B,图表 tooltip/轴是裸数字。
4. 长串数字、口径不透明等衍生体验问题。

## 定案(grilling 两轮,user 拍板)

- **口径 B**:命中率 = 缓存读 ÷(缓存读+缓存写+未缓存输入),当日口径,
  标签「当日缓存命中率」,两位小数,无封顶。
- **三比例分解**:命中率卡下堆叠条(读/写/未缓存,和恒 100%)。
- **30 天命中率趋势线**加进近 30 天图(百分比轴)。
- **工具 × 模型明细表**(工具/Token/成本/命中率);现有按工具/按模型柱状图
  tooltip 加命中率与成本(覆盖"按模型成本视角")。
- **缓存净节省 + 回本次数**当日卡:净节省 = Σ读×(input价−读价) − Σ写5m×(写5m价−input价)
  − Σ写1h×(写1h价−input价);回本次数 = 当日读 ÷ 当日写。
- **工作时段热力图**:weekday × hour,全历史,GitHub 贡献图风格。
- **万/亿单位全站**:`≥1亿 → 1.23亿`(两位小数)、`≥1万 → 4567.8万`(一位小数)、
  以下原样;FormatTokens + 排行榜 + 所有图表 tooltip/轴统一。
- 卡片网格:合并「使用工具」「使用模型」为「工具 × 模型」一卡,腾位给净节省卡。
